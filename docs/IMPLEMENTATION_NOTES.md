# 実装・設計判断の記録

このドキュメントには、機能追加や不具合修正で行った変更と、その判断理由を記録します。
コードだけでは分かりにくい設計意図を、後から確認できる状態にすることが目的です。

## 記録方針

実装や修正を行う際は、次の内容を基本として記録します。

- 何を変更したか
- なぜ変更したか
- なぜその方法を選んだか
- 他に検討した方法
- 確認方法と結果

小さな文言修正や自動整形など、設計判断を伴わない変更は関連する記録へまとめる場合があります。

## 記録テンプレート

```md
## YYYY-MM-DD: 変更内容のタイトル

### 何を変更したか

変更した機能やファイルを簡潔に記載します。

### なぜ変更したか

利用者が困っていたことや、解決したい問題を記載します。

### なぜこの方法を選んだか

既存設計との関係、変更範囲、保守性などの判断理由を記載します。

### 他に検討した方法

採用しなかった方法と、その理由を簡潔に記載します。

### 確認

実行したビルド、テスト、画面確認などを記載します。
```

選択中は既存チェック欄を再利用することで、行内の情報量とタップ領域を増やさずに済みます。
選択IDは表示中の配列ではなくリスト全体を基準に管理し、フィルター変更後も保持できるようにしました。

### 他に検討した方法

- 各行へ選択用チェック欄を常時追加する
  - 完了チェックと並んで用途が分かりにくくなり、通常時のUIが混雑するため不採用
- 表示中のタスクだけを選択対象として管理する
  - フィルター変更時に選択が消え、複数条件をまたいだ削除ができないため不採用
- 完了済み一括削除だけを使う
  - 未完了を含む任意のタスクを選べないため、別機能として選択削除を追加

### 確認

- `npm run build` 成功
- TypeScript検査成功
- 個別削除と複数削除が同じ確認モーダルを使用することをコード上で確認

## 2026-10-02: 別タブの古い内容による上書き防止（Issue #3）

### 変更・理由

メモ・ToDoに共通の保存ガードを追加した。初回に読み込んだ値と保存直前の値を比較し、違っていれば保存を停止する。storage/focusイベントでも検出し、保存停止と確認付き再読み込みを案内する。競合後も未保存の内容は画面に残す。保存キーとJSON形式は維持した。

### 方法と代替案

イベントだけでは通知前の保存を防げないため、同一キーの比較・書き込みをWeb Locksで直列化した。自動マージは削除との衝突など仕様が広がるため採用しなかった。ロック非対応・読書込エラーでは安全側に保存停止する。旧コードの直接removeItemはガードを通らないため除去し、初期値への置換もガード経由にした。ただし解析できないデータの保護・復旧は未解決。旧版の開きっぱなしのタブはロックを使わないため、全タブの更新が必要。

### 確認結果

- Node.js単体テスト: 27件成功。旧方式の上書き条件、同時保存、連続保存、外部削除、再読込後の再開、キー独立、エラー時の停止を含む。
- 型チェック・本番ビルド: 成功。
- 隔離したEdgeでlocalhostの本番ビルドを2タブ操作: メモ・ToDoの別タブ更新警告、競合後の編集で保存内容を変えないこと、メモの再読み込みキャンセル・承諾・保存再開を確認。
- 幅390pxで警告表示と横スクロールなしを確認。ブラウザの未処理エラーなし。
- requesting-code-review Skillによる別エージェントの差分レビュー: 修正必須の指摘なし。
- 実ブラウザでの厳密な同時書込、Safari/Firefox、保存容量超過は未確認（制御ロジックは単体テストで確認）。

### 確認結果

- npm test: 52件成功。今回25件追加。
- npm run typecheck / npm run build: 成功。
- 隔離Edgeの本番ビルドで、メモの不正JSON・空文字・部分不正、ToDoの不正JSON・部分不正について、再読み込み後の原文一致、該当編集画面の停止、正常側の保存を確認。
